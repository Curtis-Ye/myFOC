## delta_angle 调试窗口恒为 0 的诊断与修复
- 用户回退了 11-20 的 I2C 单点采样方案，改为 float 角度制（current_angle / last_angle 单位都是度），并把 delta_angle 提升为全局量便于观察。
- 根因：main.c 的 TIM3 回调里先 `last_angle = current_angle;` 再 `delta_angle = current_angle - last_angle;`，顺序颠倒 → 差值恒为 0，与电机是否转动无关。且用户写的 get_raw_velocity() 全工程无调用点，归一化/死区逻辑从未执行。
- 次因：死区 `±1` 的单位从 LSB 变成「度」后等于 ±1 度，会吃掉手转的微小角度差；工程 `<Optim>4</Optim>` 下 delta_angle 非 volatile，调试器可能读到滞后值。
- 修复（3 个文件）：get_raw_velocity() 改为「先算差 → 归一化 → 更新 last_angle → delta_angle 存原始差值 → 死区只作用于速度输出(0.1°)」；中断改为调用 get_raw_velocity() 并存入新增的 g_velocity；delta_angle 加 volatile；control.h 注释同步。
- 编译验证：Keil UV4 -j0 -b → 0 Error / 0 Warning，Code=18212 RO=776 RW=92 ZI=2044。
- 关键设计：delta_angle 保留未经死区的原始角度差供调试观察，静止时会有 ±0.088°(1 LSB) 的正常抖动；g_velocity 经死区平滑，静止为 0。
- 残留架构风险：current_angle 仍由主循环 encoder_task() 阻塞式读 I2C 更新，与 TIM3 2kHz 中断不同步，delta 会间歇为 0/跳动；上一轮的 I2C 单点采样方案已被用户回退。
- 物理限制：每周期测速下 1 LSB(0.088°) 对应 176°/s，硬死区必然吃掉低速；做速度环建议改分频累计测速 + 低通滤波。

## 速度闭环（VELOCITY_LOOP）振动/啸叫 + delta_angle 恒 0 诊断（仅分析，未改代码）
- 用户新增 pid2 / velocity_control() / get_velocity()（原 get_raw_velocity 改名），main.c 打开 VELOCITY_LOOP，目标常数 10 度/s；init.c 里 velocity_control_init() 已加。
- delta_angle 恒 0：get_velocity() 每周期被调用两次——velocity_control() 内部一次(control.c:142) + main.c:140 遗留的 g_velocity = get_velocity() 一次。第二次时 last_angle 已被更新，且中断期间主循环挂起、current_angle 不变 → delta=0，覆盖 delta_angle 与 g_velocity。
- 振动/啸叫根因：12 位 1 LSB=0.088°，×2000(2kHz)=176°/s 量化步长；死区 0.1°=200°/s 把目标 10°/s 完全吃掉；Kp=1000 使饱和阈值只有 30°/s，远小于噪声步长 → Uq 每 0.5ms 在 +10000 与 -30000 间满幅翻转，形成极限环。纯 P（Ki=Kd=0）无滤波。
- 加剧因素：current_angle 由主循环 encoder_task() 阻塞式 I2C 更新，与 TIM3 2kHz 不同步；电角度 elec_angle = current_angle*POLE_PAIRS 无零点校准，可能正反馈。
- 建议：只调一次 get_velocity 并把反馈传参；分频累计测速(N=20 → 分辨率 8.8°/s) + 一阶低通；Kp 降到 10~30 重新整定、Ki 配套；调试期把 UQ_MAX 临时限到 3000 保护电机；做电角度零点校准。
- 环境事实：Keil Optim=4，TIM3 2kHz，AS5600 400kHz I2C，POLE_PAIRS=7，UQ_MAX=30000。
- 调试安全：振动啸叫时应立即降低母线电压/输出限幅，避免驱动或电机过流。

## Kp=30 / Ki=1 抖动诊断（17:05，仅分析未改代码）
- 用户把 velocity_control_init 里 Kp 改成 30、Ki 改成 1.0f，电机持续抖动。
- 根因：PID.c:30 积分 `integral = sum_error + current_error` 没有乘 dt，速度环以 2kHz 调用 → Ki=1 的等效积分增益 = 1/0.0005 = 2000 倍；且反馈每 10ms 才更新，同一 error 被连续累加 20 次。
- 数值：目标 50°/s、静止时 error=50 → 20 次调用(10ms) 就把 sum_error 顶到 integral_limit=1000 → 积分输出 1000 Uq，加 P 项 30*50=1500 共 2500（限幅 3000）。反馈低通 alpha=0.2 有 50ms 滞后，误差长期同号 → 严重超调；反馈追上后 error 反号、输出翻到 -3000 急刹，循环成几 Hz~十几 Hz 低频极限环。
- Kp=30 不是主因（噪声经低通后 P 项波动仅几百 Uq）。
- 立即止血：Ki 设回 0 验证（不抖即确认积分是元凶）；当前结构下 Ki 应从 0.01~0.05 起步，不是 1。
- 结构性修复建议：速度环 PID 只在 velocity_updated 时计算（100Hz 与反馈同步），积分乘 dt=0.01，integral_limit 改为限制积分输出而非 sum_error；VEL_LPF_ALPHA 0.2→0.4~0.5 或 VEL_DIV 20→10 以减小滞后。
- 待确认：elec_angle_offset 是否仍为 0；未标定时力矩方向可能错，同样会抖（高频尖叫型）。

## 重新通读代码：uq_sign 修复无效的根因分析（本轮，未改代码）
- 用户反馈「不论怎么改 uq_out 还是 3000 或 -3000」，方向翻转修复无效 → 上一轮「全局力矩方向反了」判断不完整，予以推翻。
- 代码可证：uq_out = uq_from_float(pid_output * uq_sign)；pid_output 被 PID.c 的 min/max 钳在 ±VEL_UQ_MAX=±3000；uq_from_float 只钳 ±30000，±3000 原样通过。故 ±3000 是硬上限。Kp=30 → 线性区仅 |error|<100 °/s（target=50 时 v∈(-50,150)）；v≈±3100 时必饱和。uq_sign 只翻符号不脱饱和；uq_out 是每 0.5 ms 被 ISR 重写的输出量，Watch 里手写会被立刻覆盖；VEL_UQ_MAX 是宏需重新编译。
- 关键推论：单纯「力矩符号反」一定能被符号翻转修好（k<0 → k>0）。翻了仍飞转 ⇒ 不是纯符号问题，剩余嫌疑：①改动未烧录/改错变量；②速度反馈 v 不忠实（current_angle 冻结/跳变/符号与真实转向不一致），使 50-v 永不收敛；③电角度相位未标定。
- 新发现：elec_angle_offset=20.0f 在 7 对极下 = 140° 电角度，本身就能反转力矩；且 uq_sign 翻转 ≡ 电角度 +180° ≡ 机械角 +25.7°，二者是同一个自由度，未标定零点时来回翻符号等于盲猜。
- 新发现：current_angle 由主循环阻塞式 AS5600_ReadAngle() 产生，而 get_velocity()/FOC_control() 在 TIM3 2 kHz ISR 里消费，无同步。AS5600_ReadRawAngle() 有 2×3ms 重试 + HAL 固定 25ms BUSY 等待 + AS5600_I2C_Recover()(DeInit/Init)；一旦读失败，current_angle 冻结数十 ms，测速与换相角度同时失效 → 振动/啸叫/假速度尖峰。排查量：g_angle_updates / g_angle_errors / AS5600_FailCount / AS5600_ConsecFail / AS5600_LastSR1。AS5600_ReadDiagnostics() 全工程未被调用，Status/Agc/Magnitude 恒 0。
- 新发现：FOC.h 的 FOC_CALL_FREQ=10000 与实际 TIM3 2 kHz 不符；FOC_OpenLoop_Update() 的开环磁场频率实际是标称的 1/5（open_loop_elec_freq=2 → 实际 0.4 Hz 电角度 ≈ 20.6 °/s 机械），开环测试要按 5 倍设置，别误判为不动。
- 结论/给用户的调试路线：Step0 把 VEL_UQ_MAX 改成 1000 重编译下载，若 uq_out 仍 3000 → 烧的是旧固件；Step1 断开速度环用 OPEN_LOOP 验证 PWM/相序/驱动；Step2 手转电机验 current_angle/delta_angle/g_velocity 符号与 I2C 计数；Step3 开环固定 Uq+固定电角度对齐转子，实测 elec_angle_offset 并单独定 uq_sign（把两个符号问题拆开）；Step4 target=0、Kp 降到 2~5、VEL_UQ_MAX=1000 闭环验证阻尼；Step5 再给 50 °/s 加 Kp/Ki；Step6 才做 P2（I2C 采样移入 TIM3 中断）。PID.c 积分无 dt，Ki 只能取 0.01~0.05。
