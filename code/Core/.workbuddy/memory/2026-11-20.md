## AS5600 速度变量跳变问题诊断（仅分析，未改动代码）
- 根因：main.c:10-11 把 current_velocity_angle / last_velocity_angle extern 声明为 `volatile float`，而 control.c:23-24 定义为 `volatile uint16_t`。跨编译单元类型不一致，链接器只按符号名匹配不检查类型 → 中断里 4 字节 float 写踩踏相邻变量，且 IEEE754 位模式低 16 位被按整数显示，静止时 ±1 LSB 抖动被放大成上万跳变。
- 其他问题：I2C 在主循环 encoder_task() 与 TIM3 中断（优先级 0）并发调用 AS5600_ReadRawAngle，阻塞式 HAL_I2C_Mem_Read 重入；0xFFFF 失败值在中断路径未过滤；control.c:91-98 回绕条件自相矛盾恒为假；delta*2000 溢出 int16_t；TIM3 实际 2 kHz（72MHz/72/500）但 CTRL_FREQ_HZ 写 1000.0f。
- 建议架构：I2C 只在 TIM3 中断单点采样，主循环不碰；变量声明统一放 control.h；速度返回 int32_t；加死区/低通抑制 12 位量化噪声（1 LSB≈0.088°，2kHz 下 1 LSB=2000 LSB/s）。
- 项目事实：AS5600 挂在 I2C1 @400kHz，7 位地址 0x36；POLE_PAIRS=7；TIM1 PWM 40kHz；TIM3 2kHz。

## 补丁已落地（同日第二轮，用户要求改到文件里）
- 改动文件：Core/Inc/control.h、Core/Src/main.c、Core/Src/control.c 共 3 个。
- control.h：新增两个 uint16_t 变量的 extern 声明；get_raw_velocity 返回类型改 int32_t；约定跨文件共享变量只在头文件声明一次。
- main.c：删除错误的 float extern 和 encoder_task()；temp 改 volatile int32_t；I2C 只在 TIM3 回调单点采样，成功时同步更新 current_angle / 角度快照 / temp / g_angle_updates，失败时速度置 0 且 g_angle_errors++；主循环只保留 get_angle()。
- control.c：CTRL_FREQ_HZ 1000→2000；回绕判断修正为 ±2048 阈值 ±4096 补偿；delta 改 int32_t；加 ±1 LSB 死区；返回 LSB/s。
- 编译验证通过：D:\Keil_v5\UV4\UV4.exe -j0 -b MDK-ARM/myFOC.uvprojx → 0 Error / 0 Warning（ARMCC V5.06 update 7），Code=17630 RO=774 RW=88 ZI=2048。
- 残留风险：AS5600_I2C_Recover() 仍可能在 TIM3 中断上下文执行；阻塞式 I2C 在 2kHz 中断里耗时较大；每周期测速下 ±1 LSB 死区会吃掉约 176°/s 以下的真实速度，做速度环时建议改分频累计测速。
- 约定：PID.c 的 Kd 项不含 dt，CTRL_FREQ_HZ 宏不参与 PID 运算，改宏不改变实际行为（实际频率一直 2kHz）。
