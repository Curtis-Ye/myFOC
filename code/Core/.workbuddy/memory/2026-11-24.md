## Keil 编译失败诊断与修复

- 现象：Build 报 `startup_stm32f103xb.s(131): error: A1207E: Bad or unknown attribute`，1 Error / 0 Warning，Target not created。日志在 `code/MDK-ARM/myFOC/myFOC.build_log.htm`（µVision 5.38 / ARMCC 5.06 update 7）。
- 原因：编辑时误删换行，把 `IMPORT SystemInit` 与 `LDR R0, =SystemInit` 挤到第 131 行同一行；armasm 的 `IMPORT` 语法是 `IMPORT symbol [attr]`，多出来的 `LDR ...` 被当作"属性"解析 → A1207E。
- 修复：已把 `code/MDK-ARM/startup_stm32f103xb.s` 第 131 行恢复成两行，并用 `D:\Keil_v5\ARM\ARMCC\Bin\armasm.exe --cpu Cortex-M3` 在纯英文临时目录单独汇编验证：exit=0，生成 4568 字节 startup.o。
- 验证结论：C 文件全部编译通过（各 .o 时间戳均新于对应 .c：main.o 23:50、tim.o 23:39、control.o 21:20、foc.o 21:06），uvprojx/uvoptx 差异仅为 CRLF 行尾，无其他编译错误。重新 Build 应能通过。

## 顺带发现的参数不一致（非编译错误，但会让低速抖动更糟）

1. `tim.c` Period 499→99 → TIM3 中断 2 kHz→**10 kHz**，但 `control.c` 的 `CTRL_FREQ_HZ` 仍为 2000、`VEL_DIV` 仍为 20：测速窗口实际变成 2 ms，`v_raw = d * (2000/20) = d*100`，正确应为 `d/0.002 = d*500` → **速度读数系统性缩小 5 倍**；速度环变成 500 Hz 计算，积分等效增益再放大 5 倍；分辨率从 8.8 °/s 恶化到 44 °/s。需改回 Period=499，或同步把 CTRL_FREQ_HZ 改 10000 并重调 VEL_DIV/PI。
2. `control.c` 把 `elec_angle_offset` 32.0→0.0、`uq_sign` -1→1：把 git HEAD 里已标定的值退回未标定，可能让速度环变正反馈、低速抖动复现。
3. `main.c` 的 `POSITION_LOOP` 分支里 `velocity_control(usart_data)` 少传一个参数，语义上应为 `position_control(usart_data)`；当前宏未开启故被预处理器排除，不影响本次编译。
4. `FOC.c` `open_loop_Uq` 6000→10000，注释仍写"约 6%"（实际约 15%）。
5. `main.c` SIMPLE 模式目标速度 -3600→100 °/s，正好落在上次分析的低速抖动区间。
- 备注：`main.h` 的枚举现在是 `SIMPLE / USART`（上次会话读到的是 `SIMPLE_MODE / USART_MODE`，用户已改过）。
